# Figures

Diagram **source** for the survey. Render each `.mmd` to SVG/PDF for the paper
(`mmdc -i fig1-taxonomy.mmd -o fig1-taxonomy.pdf`), then a designer polishes typography
and colour for camera-ready. `fig4-datapath.md` carries flow logic + a spec for a
hand-drawn vector version.

## Figure 1 — draw.io

`fig1-taxonomy.drawio` is the editable source of record (open in the desktop app or
app.diagrams.net). It is generated by `../scripts/gen_fig1.py`, which reads
`../data/inventory.csv` so the per-axis counts stay in sync with the corpus. To rebuild:
`python scripts/gen_fig1.py`. The `.mmd` version is kept as a lightweight fallback only.

**LaTeX side is already wired** (`\surveyfig` macro in the preamble; the float sits in
section 4, right after "Fig. 1 depicts it as a tree." and before the Table 1 longtable,
`\label{fig:taxonomy}`). Until the PDF exists, `1bit-llm-survey.tex` still compiles: it
falls back to a boxed placeholder that names the missing file. The one remaining manual
step, since no `.drawio` renderer is available in this environment:

1. Open `fig1-taxonomy.drawio` in the draw.io desktop app or https://app.diagrams.net.
2. **File -> Export as -> PDF**, tick *Crop*, tick *Transparent Background* off.
3. Save as `figures/fig1-taxonomy.pdf` (exact name/path the macro expects).
4. Re-run `make pdf` (or `pdflatex`) — the real figure replaces the placeholder automatically.

(If draw.io desktop is installed elsewhere, its CLI does this in one line:
`drawio -x -f pdf --crop -o figures/fig1-taxonomy.pdf figures/fig1-taxonomy.drawio`.)

## Pre-rendered pgfplots/TikZ figures (3, 4, 6, 7, 9, 10, 11, 12)

These eight figures (nine files, since Fig 12 is two stacked panels) used to be raw
`tikzpicture`/`pgfplots` `axis` code embedded directly in `1bit-llm-survey.tex`. As of
2026-09-14 they are pre-rendered to standalone PDFs instead, because pgfplots' per-figure
coordinate/tick/axis computation was the single biggest cost in compiling the main
document, and on Overleaf's shared/free-tier compile servers that cost was pushing the
build past the compile timeout. The main document no longer loads `pgfplots` or `tikz`
at all; it only `\includegraphics`'s the pre-rendered PDFs below. Locally this cut a full
3-pass compile (`pdflatex`, `bibtex`, `pdflatex` x2) from about 14.3s to about 4.8s.

**Two-step regen, whenever the underlying data or the figure code changes:**

1. `python scripts/build_paper.py` — recomputes every figure's TikZ/pgfplots body from
   `data/*.csv` and `repro/` and writes it to `figures/fig-<slug>.tex` (a standalone
   document, not the main paper). This step also rewrites `1bit-llm-survey.tex`, so it
   always runs anyway as part of the normal build.
2. Compile the changed standalone file(s) with `pdflatex` directly in this directory,
   e.g. `pdflatex fig-growth.tex`. This is a manual/scripted step, not something
   `build_paper.py` does itself (consistent with how `fig-roadmap.tex` already works,
   see below) — it needs its own `pdflatex` process, and MiKTeX/TeX Live must already be
   on `PATH`. To rebuild all nine in one pass:
   ```
   cd figures
   for f in fig-ste fig-growth fig-heatmap fig-weightyear fig-systemsvenn \
            fig-effbits fig-controlledpairs fig-efficiency-bars fig-efficiency-scatter; do
     pdflatex -interaction=nonstopmode "$f.tex"
   done
   ```
   Commit the regenerated `.pdf` files alongside the `.tex` sources — Overleaf (and
   anyone else building this paper) needs the PDFs present as static assets, since the
   main document no longer computes them at compile time.

**Two things to know if you touch `_standalone_tex()` in `build_paper.py`:**

- The `geometry` line in every standalone file's preamble must stay byte-identical to
  the main document's (`\usepackage[a4paper,margin=0.85in]{geometry}`). Several figures
  use pgfplots `width=0.6\textwidth`-style options, and `\textwidth` must resolve to the
  same absolute length here as it would embedded in the main document, even though
  `standalone` crops the final PDF to the content's bounding box regardless of the
  nominal page size.
- `standalone`'s automatic bounding-box detection under-measures a pgfplots axis with a
  `title=` or a rotated `ylabel=`/`xlabel=`, clipping the top or side of the text. The
  fix in place is a generous symmetric border, `\documentclass[...,border={14pt 14pt
  14pt 14pt}]{standalone}` — don't remove it, and if a new figure still shows clipping
  at that border width, increase it further rather than trying to compute the exact
  shortfall (it varies by title/label length and isn't worth chasing precisely).
- **One `tikzpicture` per standalone file, not two.** The `tikz` class option makes
  `standalone` export one PDF *page* per top-level `tikzpicture`, and `\includegraphics`
  without a `page=` option silently takes only page 1 — so a second `tikzpicture` in the
  same file (there used to be one for Fig 12's bar chart and a second, below it via
  `\vspace`, for the Pareto scatter) is dropped from the document with no warning. Fig 12
  is therefore two separate files (`fig-efficiency-bars.tex`, `fig-efficiency-scatter.tex`)
  stacked with two `\includegraphics` calls and a `\vspace{3mm}` between them in `FIG5`,
  matching the original layout. If a figure ever needs more than one panel again, split
  it the same way rather than concatenating `tikzpicture`s in one file.

**Fig 8 (`fig-datapath.drawio`) is the one exception to "generator writes the `.drawio`":**
as of 2026-09-11 it is edited by hand directly in draw.io. `scripts/gen_fig4.py.deprecated`
(renamed so it can't be run by habit) used to generate it from `fig-datapath.md`; both are
now stale reference material only. Don't regenerate this file from either of them -- edit
`fig-datapath.drawio` itself, then re-export the PDF. The current design uses blue for the
activation quantizer, orange for the weight quantizer, purple for the shared ternary
matmul (identical across all three panels, which is the whole point of the figure), and
green / red for each variant's one unique step (the Hadamard rotation in (b), top-K
sparsification in (c)). If you change the colors again, update the LaTeX caption in
`build_paper.py` (`FIG4`) to match -- it names the colors explicitly, and a stale color
description in the caption is the exact bug this figure has hit twice already.

## Fig 1 — `fig-roadmap.tex` (standalone)

Built with the `standalone` class + `forest` `[edges]` so the main paper only needs
`\includegraphics` (no `forest` in `1bit-llm-survey.tex`). To rebuild after any
section/subsection rename: edit `fig-roadmap.tex`, run `pdflatex fig-roadmap.tex` in
this directory, commit the regenerated `fig-roadmap.pdf`. `build_paper.py` wires it as
`\includegraphics[width=\textwidth]{fig-roadmap.pdf}` with `\label{fig:roadmap}`,
referenced from Section 1.6. Sections 8 and 10 are grey-shaded (`contrib` style) to mark
the paper's analytical contribution.

The PRISMA / corpus-selection figure was removed with the systematic-review framing.
Fig 1 and Fig 2 counts are generated from `../data/inventory.csv`; re-run the generators
after any corpus change, then re-export the PDFs. The `.drawio` files carry a
`fontSize=15; strokeWidth=3` style that the generators emit directly.
